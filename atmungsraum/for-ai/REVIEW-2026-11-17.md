## Findings

### R1 — P2: Technical Polar retirement switches the selected input to Automatic

**Location:** native `apps/native-renderer-android/native/src/experiment_breathing_setup.rs:1329–1330`.

`invalidate()` replaces every Polar input with Automatic when a clock/source
failure retires its model and live observations. A continuous PCM observation
after a 300 ms poll gap is sufficient. Calibrated, fixed and adaptive Polar are
all affected without an operator method change.

This bypasses retained manual breathing-state integration. The runtime derives
the renderer's input namespace from this changed selection; the driver's
Automatic branch resets its integrator directly to the scheduled envelope
(`breath_composition_driver.rs:391–396`). This can jump the radius, including
to minimum during the minimum phase, and leaves Automatic selected afterward.

**Reproduction:** The unchanged production core reproduces the change in all
three Polar modes for clock gaps/stalls. The actual compiled native Runtime's
stdio peer confirms fixed Polar/hold/ready at frame 88200 becoming
Automatic/volume 0.575/not-ready after the next continuous observation at
frame 101430. The failure is `clock_stale`; the current clock observation itself
is valid. Source-clock retirement also reaches this invalidation. Ordinary BLE
silence alone is not asserted to change the source binding.

**Recommendation:** Retire readiness, model and confirmations independently of
the selected manual visual namespace. Preserve the last diagnosed manual phase
through technical unavailability. Add a Runtime-to-driver regression for each
retirement and all three Polar methods, including a minimum-phase observation.

### R2 — P2: An old preparation journal blocks Pause and Finish for a current session

**Location:** [quest-ui.js](../quest-ui.js), lines1254–1255; supporting global
waiting/Finish gates at437–439 and636.

`act()` refuses all experiment actions while `breathing.pending` exists, even
when the current native session is RUNNING, recording, has no pending native
command, and confirms that this phone has control. An unresolved preparation
request can therefore disable both Pause and Finish indefinitely.

**Trigger:** Phone A retains a lost/unknown Controller-selection request. A
different saved phone sets up and starts a session. A subsequently reconnects
and acquires free control. The old preparation journal is still preserved, as
required for uncertain work, but its recovery acknowledgement requires native
IDLE (`breathing-setup.js:184–186,253`). It cannot be retired through the UI
while the current session runs.

**Reproduction:** The mounted production PWA with the persisted journal and
fresh current RUNNING/rec:true/pending:false status remains on the running page
with Finish disabled after 16 seconds. No commands or setup replays are sent.

**Recommendation:** Keep the original uncertain journal and read-only receipt
reconciliation. Separate its preparation guard from independently fenced
current-session Pause/Finish controls; do not erase or replay the old request.

### R3 — P2: Protected kiosk escape can leave a boot watch armed

**Location:** native
`apps/native-renderer-android/src/main/java/io/github/mesmerprism/rustyquest/native_renderer/NativeRendererSelfKioskService.java:244–252`.

The protected three-menu escape enters `dispatchTerminal()` directly. It does
not call `NativeRendererMetaUpdate.intentionalExit()`, unlike the explicit app
and remote exit paths. Its `invalidatePending()` call only retires the updater;
retirement does not cancel the helper watch. Generated terminal admission and
finish paths also omit cancellation.

**Trigger:** A boot watch still awaits the focused-ready acknowledgement when
the user deliberately escapes. For example, acknowledgement can be queued
behind the updater worker's policy fetch. A later package replacement during
that same boot can then cause the helper to launch the app again after escape.

**Reproduction:** Actual kiosk coordinator, foreground policy and helper watch
policy, plus the extracted production terminal dispatcher, produce
`terminal=true`, one terminal route, zero cancellation calls and a retained
boot watch. An installed-version change then causes one fallback launch.
Platform calls are modeled; this does not claim a new device observation.

**Recommendation:** Cancel the helper watch from the common admitted intentional
terminal path, with durable cancellation before closure. Preserve the distinct
queued-update exit's deliberate retention of its armed update watch.

### R4 — P2: Locally saved Quest recordings become inaccessible when disconnected

**Location:** [quest-ui.js](../quest-ui.js), lines659–660; `selectArchive()` at882.

The archive selector and download link are hidden when live `status` disappears.
Disconnect also clears the archive list. Loading the stored list and selecting
an archive both require a current gateway, although the validated file has
already been committed to the phone's IndexedDB store.

**Reproduction:** A synthetic archive committed through the production store is
downloadable while connected. After Disconnect → Aufnahmen, the page remains
reachable but both archive controls disappear. The same file remains in
IndexedDB. This is loss of access through the UI, not file deletion.

This obstructs the stored-copy recovery described in
[DATA-LOGGING.md](DATA-LOGGING.md#native-recording-synchronization) when the Quest
is unavailable.

**Recommendation:** Enumerate and open committed local archives using the saved
verified device identity independently of a live connection. Keep gateway and
native-idle requirements for synchronization and native data access.

### R5 — P3: A timed-out update handoff can still apply its kiosk side effect

**Location:** native
`apps/native-renderer-android/src/main/java/io/github/mesmerprism/rustyquest/native_renderer/NativeRendererMetaUpdate.java:114–119`.

The shared install handoff posts a main-thread runnable and waits five seconds.
Unlike the queued-exit dispatcher, it has no expiration flag or monotonic
deadline. If the main thread executes the runnable after the wait timed out,
it can still latch `handoffForMetaInstall()` and disable foreground recovery,
although the caller received false and did not dispatch SDK installation.

**Reproduction:** The extracted production method returns false with zero kiosk
latch calls; executing its delayed runnable afterward produces one latch call.

The coordinator already makes this failure irreversible and requires restart,
so a new experiment is not currently admitted by this race. Its additional
impact is a late kiosk-state change during an already failed update attempt.
This is lower priority than R1–R4.

**Recommendation:** Give the shared handoff the queued dispatcher's expiration
and deadline checks, including a check after owner validation.
