# Atmungsraum guidance

Read `for-ai/README.md` in this directory before changing this subproject.
Also follow the repository's root `AGENTS.md` and `for-ai/` constraints.
Keep the subproject notes current with changes to its behavior or workflow.
Before any participant data logging change, read `for-ai/DATA-LOGGING.md` and
reuse its shared identity/filename writer. This applies to every data stream.

At project entry, read `for-ai/SKILLS.md` for the nested `for-ai`, RTK, GSD Core,
Superpowers and Ponytail baseline, plus conditional UI/accessibility/performance
and native/remote routes. Resume the durable goal and active checklist in
`for-ai/PROJECT.md` (or the existing GSD state it points to).

Before ending, update that same state with verification evidence, blockers,
the next action and observed Git/publication state. Keep the overall product
goal open until its own acceptance criteria pass. Use Git for rollback and
preserve unrelated work; do not create duplicate progress or source trees.

Follow the user's standing Superpowers/GitHub synchronization instruction in
the root `for-ai/constraints.md` and local `for-ai/WORKFLOW.md`. Complete the
applicable Superpowers checks, update For-AI evidence, then commit and push
verified completed work without requesting the same permission again.
Publish each completed verified increment promptly to the live URL as well as
GitHub. Do not wait for another request; verify the exact Pages deployment and
affected live assets/behavior before handing off. See the 2026-11-06 root rule.
